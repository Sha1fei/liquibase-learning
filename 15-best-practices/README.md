## Лучшие практики
-   ```Один changeSet — одно логическое изменение``` (принцип атомарности и простоты отката) - разделение создания таблицы, добавления внешних ключей и наполнения данными на разные changeSet
-   ```Идемпотентность и обратная совместимость (Zero-Downtime)``` (безопасное обновление БД без остановки сервиса) - паттерн Expand & Contract: сначала добавляем новую колонку, переносим код, затем удаляем старую
-   ```Никогда не менять выполненные changeSet``` (сохранение целостности аудита и контрольных сумм) - любые правки и исправления ошибок оформляются только новыми `changeSet`
-   ```Обязательный блок rollback``` (гарантия возможности отката при аварийном релизе) - каждый changeSet должен содержать корректный план отката
-   ```Использование Preconditions с осторожностью``` (предотвращение ложного пропуска миграций) - избегать чрезмерных условий, скрывающих проблемы рассинхронизации сред
-   ```Проверка миграций через updateSQL в CI/CD пайплайне``` (ревью сгенерированного SQL кода перед релизом) - автоматическая проверка безопасности DDL операций до попадания в production
-   ```Разделение DDL (структура) и DML (данные)``` (управление транзакциями и временем блокировки таблиц) - изменение структуры и тяжелые миграции данных выполнять в разных шагах

## Структурирование и подключение файлов
-   ```include file="..."``` (подключение отдельного файла миграции в главный changelog) - разбиение монолитного файла на независимые логические части
-   ```includeAll path="..."``` (автоматическое пакетное подключение всех changelog файлов из папки) - подключает все файлы в алфавитном порядке; избавляет от ручной регистрации
-   ```relativeToChangelogFile="true"``` (разрешение путей относительно текущего файла, а не classpath) - делает структуру миграций переносимой и модульной
-   ```master changelog pattern``` (архитектурный шаблон организации версий БД) - единый корневой `db.changelog-master.yaml`, подключающий папки `v1.0`, `v1.1`, `seeds`
-   ```структура по версиям (db/changelog/changes)``` (разделение миграций по спринтам, релизам или сущностям) - упрощает разрешение конфликтов при параллельной командной разработке
